Startup Functions (Logical Order)

Back to docs index

This page documents the root application startup flow from the main binary entry point, in execution order.

  1. Panic hook is installed : `std::panic::set_hook(...)` writes startup probe details and runtime events if a fatal panic occurs.
  2. Raw argument and runtime context snapshot : captures args, launch mode, terminal/GUI detection, and writes probe data.
  3. CLI parsing : `Cli::parse()` resolves command-line options and flags.
  4. Desktop launcher maintenance commands : optional early exit for install or uninstall desktop launcher commands.
  5. Runtime directory alignment : `align_process_working_dir_to_runtime_layout()` aligns execution context for portable/runtime layouts.
  6. Review UI auto-enable decision : if launched without args from interactive terminal or GUI session, review UI is enabled by default.
  7. Config load and template assurance : `load_config("config.toml")` and `ensure_config_and_template_files(...)` run early.
  8. Review UI path (if enabled) : validates OS, verifies desktop integration, then starts startup selector via `run_review_ui_bootstrap(...)`, followed by `run_review_ui(...)`.
  9. Config initialization path (if requested) : `--init-config` writes or updates config and exits.
  10. Standard non-review validation path : user input, year range, logging, OS, and source validation execute in order.
  11. Mode dispatch : startup routes to database mode or scraping mode based on validated source and inputs.

Primary implementation reference: `src/main.rs` in the root application.
