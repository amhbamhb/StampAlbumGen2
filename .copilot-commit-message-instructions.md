# Commit message generation instructions

Rules:

- always refer to docs/AUTOMATION_QUICK_REFERENCE.md, docs/AUTOMATION_SETUP.md, docs/AUTOMATION_SYSTEM_DOCUMENTATION.md for standard conventions and context.
- Always produce two messages in the response: a short "SIMPLE" message and a longer "DETAILED" message.
- SIMPLE: single-line, imperative tense, <= 50 characters, optional scope in parentheses or square brackets.
- DETAILED: less than 4000 char describing what changed, why, and any important notes (migration steps, breaking changes, tests).
- If the branch name or diff references a ticket (e.g. ABC-123), include the ticket id in both messages.
- Prefer "fix:", "feat:", "chore:", "docs:", "refactor:" prefixes when applicable. as stated above in the docs above
- If the change is a hotfix, prefix with "hotfix:" in SIMPLE.

Examples:

## Example 1 — bug fix

SIMPLE:
fix(pagination): correct off-by-one error in page count

DETAILED:
Fixes an off-by-one error in the pagination logic that caused the last page to be skipped when item count is an exact multiple of the page size. The root cause was an incorrect inclusive boundary check; adjusted the condition and added unit tests covering boundary cases. No DB migrations required. Manual QA: verify paging on lists with 10, 20, and 25 items.
